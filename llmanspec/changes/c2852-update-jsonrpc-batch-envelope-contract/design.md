# Design — batch 收窄的显式化决策

## 决策表

| # | 决策 | 取舍 |
|---|---|---|
| D1 | 文档化拒绝而非实现 batch | 无产品消费者（remote driver 全 unary）；batch 需定义逐元素幂等键与写者租约准入语义，纯属为不存在的客户端堆面。 |
| D2 | 拒绝形态 = 既有非法信封路径（`None` → HTTP 400） | 不发明新错误码；与「缺 method / 载体不符」同梯队，单测已有非法信封矩阵可扩一行。 |
| D3 | spec 措辞锚「文本调试通道」 | 产品路径是 v3 二进制帧；JSON-RPC 文本是调试通道（PROTOCOL_VERSION=3 注记）——batch 拒绝只约束调试通道，不涉 v3。 |

## 失败模式

- 未来若真需 batch：走新 change 扩契约（幂等键/租约语义一并定义），本规则措辞不阻碍。
