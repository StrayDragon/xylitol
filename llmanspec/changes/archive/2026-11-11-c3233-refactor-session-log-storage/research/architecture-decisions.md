# c3233 架构选型记录（ADR 全景）

2026-11-11 对齐产物。每项：选型 | 备选 | 为什么 | 解决了什么 | 缺陷 | 改进/逃生口。

## ADR-1 真值模型 = 追加事件日志

- 备选：多文件+manifest 修补（原 c3230 方案 A）；嵌入式 DB（SQLite/redb）。
- 为什么：语义模型（entry + parent 链）与物理模型一一对应；写路径缩为单点；成熟先例 git（object+ref）、Kafka（log segment）、WAL、event sourcing。
- 解决：封存四步事务（S1）、代际反推（S2）、布局判定六处（S3）、fork 分流（S7）整体消失。
- 缺陷：随机访问需索引；跨会话查询 = 扫描。
- 改进：稀疏索引（ADR-9）；触发条件后 redb/Tantivy（ADR-3）。

## ADR-2 真值格式 = 人类可读 JSONL

- 备选：二进制段（bincode / redb 文件）；混合格式。
- 为什么：cat/grep/jq 排障是产品特性；serde 词表跨引擎不变；行级前向兼容（可选字段，对齐仓库「字段级演进」规则）。
- 解决：可移植、排障成本、导入导出 = 文件本身。
- 缺陷：体积约为二进制 2-3 倍；解析慢于 bincode。
- 改进：解析只发生在窗口内（分页）；将来可选文件级压缩。

## ADR-3 引擎策略 = 文件系统 now，DB 后置（四触发条件）

- 备选：直接 SQLite；直接 redb；双写（双真值，反模式排除）。
- 为什么：单写者 + 低吞吐下 DB 收益全是理论值，依赖 / 构建 / 可读性代价立刻付；概念数 3 vs DB 路线约 8。
- 解决：复杂度预算；避免过早优化。
- 缺陷：触发日到来时需一次性迁移（重放 JSONL）。
- 改进：护栏三（JSONL 永久交换格式）保证迁移永远 = 重放。触发条件四条：跨会话搜索产品化、缓存重建超 1s、多进程并发写需求、结构化分析面。

## ADR-4 压缩 = 日志内语义标记（零搬运）

- 备选：物理搬运（现状四步事务）；物理删除旧 entry（丢回看能力）。
- 为什么：parent 链 + Compaction entry 已完整表达「旧史被摘要替代」；LLM 视图截断 / 树视图全量是同一标记的两种投影。
- 解决：S1 全部；前缀缓存只在压缩时断（可解释、可克制）。
- 缺陷：磁盘不回收（旧 entry 永在）；两条投影规则需各自维护。
- 改进：将来磁盘成问题再做保守物理回收（仅不可达子树、显式命令）。

## ADR-5 投影模型 = 三视图 + 不可变前缀缓存

- 备选：存储即视图（读什么存什么）；单一投影。
- 为什么：三消费方正交（LLM 线性 / 树全量 / 分页窗口）；日志不可变 → 按 leaf_id 缓存投影，追加后 O(delta) 折叠；确定性投影命中 provider prompt cache。
- 解决：换方言零成本；回看与发送互不干扰；恢复会话亚秒。
- 缺陷：投影规则分散会漂移（扫描 F6 同类病）。
- 改进：投影函数集中单一模块 + 属性测试（同分支必同投影）；缓存键 = leaf_id。

## ADR-6 turn = 派生规则（user entry 开界）

- 备选：显式 TurnRecord entry。
- 为什么：现有 entry 种类已足够表达；不加存储概念；轮转 / 分页 / 截断都现场数。
- 缺陷：turn 定义若变复杂（多 user 合并等），规则单点必须守住。
- 改进：turn 边界函数唯一实现 + 单测矩阵。

## ADR-7 轮转 = 双触发 + turn 对齐

- 备选：仅大小；仅压缩点；不轮转。
- 为什么：压缩点切 → LLM 视图只碰当前文件（热路径红利）；大小切 → 防单文件无界；turn 对齐 → 分页单文件完成、截断不伤半个 turn。
- 解决：文件数与文件大小双界；读放大最小化。
- 缺陷：双条件相邻触发可能产生小文件；策略测试矩阵变宽。
- 改进：接受小文件（维护任务统计可见）；过密轮转场景实现期再调。

## ADR-8 不做自动重分片

- 备选：自动重分片（64MB×10 → 16MB×40）；定期后台重整。
- 为什么：文件边界是物理细节，重分片把它重新语义化；稀疏索引已 O(1) 跳转，收益严格为零；重写冷数据需要大事务——被消灭的问题复活；Kafka / git 均不重切旧数据。
- 解决：复杂度不回潮。
- 缺陷：旧文件尺寸不均（纯美观）。
- 改进：显式 xylitol sessions repack 逃生口（未来按需）。

## ADR-9 稀疏索引（Kafka .index 式）

- 备选：全量 id→offset 映射；无索引纯扫描；DB 索引。
- 为什么：每 64 entry 一个锚点，定位 = 锚点 + 最多 63 条线性扫；体积小、重建快（全量扫描一遍）。
- 解决：travel 旧分支的 O(1) 跳转；分页跨文件。
- 缺陷：索引是第二份需一致的东西。
- 改进：索引 = 可丢弃派生（护栏二），校验失败即重建，绝不修复。

## ADR-10 分页 = page token（turn / entry 粒度）

- 备选：整数 offset；仅 entry 粒度。
- 为什么：token 编码 leaf + anchor + direction + unit + limit——树会话语义下整数 offset 无意义；turn 粒度匹配「仅加载最后 3 turn」。
- 解决：懒加载 UX（TUI HISTORY_PAGE / WINDOW 语义延续）。
- 缺陷：token 格式需版本化（格式变则失效）。
- 改进：token 内嵌版本；失效 = 从 leaf 重开（优雅降级）。

## ADR-11 维护单元 = lazy（打开快检 + CLI）

- 备选：常驻低频调度；无维护单元。
- 为什么：B 的哲学 = 派生物可丢可重建，无需主动保鲜；维护从「计划活动」降级为「按需恢复」；常驻任务本身是新状态机（本次扫描教训）。
- 解决：崩溃脏状态在下次打开自愈（截断半行、清 .tmp、缓存新鲜度毫秒级）；重维护给用户/脚本显式入口。
- 缺陷：从不打开的会话永不被维护（但也不被读，无影响）；CLI 依赖用户记得跑。
- 改进：serve 常驻形态若到来，再评估挂调度（属触发条件三的伴生）。

## ADR-12 崩溃恢复 = 截断 + 重建

- 备选：预写双缓冲；DB WAL。
- 为什么：JSONL 行是天然提交单元；半行 = 未完成；恢复 = 两条机械规则（截尾、重建缓存）。
- 解决：恢复确定性。
- 缺陷：fsync 粒度决定丢失窗口。
- 改进：fsync = turn 边界批量（已决 2026-11-11：一个 turn 一批 + 收尾批，ms 级窗口）。

## ADR-13 写锁 = OS 原语永真锁

- 备选：锁文件存在性（trust / config 现方案）；现状「无 manifest 视为持锁」。
- 为什么：flock（POSIX）/ 命名信号量（Windows）随进程消亡自动释放，无死锁文件问题；锁先于一切写创建。
- 解决：S6 双进程创建窗口。
- 缺陷：无（OS 级原语即最简）。
- 改进：无。

## ADR-14 演进护栏三条

- 内容：读写仅经 XySessionStore port；派生物一律可丢弃可重建；JSONL 永久交换格式。
- 解决：ADR-3 的升级路径永远开着（引擎可换）。
- 缺陷：port 有被绕过直读文件的风险。
- 改进：review 门禁把关；必要时加 lint 规则（禁止 session 插件外引用布局符号）。

## ADR-15 兼容 = breaking 门 + 新格式版本字段

- 备选：惰性迁移；显式迁移命令；双读兼容。
- 为什么：未推广期一步到位；迁移代码是永久债务面；新格式从 log-v1 起内嵌版本，未来走可选字段不再 breaking。
- 解决：零迁移矩阵；新格式演进自由。
- 缺陷：旧会话不可读（影响可控）；测试夹具需重造。
- 改进：错误文案清晰指路（开新 session）；导出工具可后补抢救数据。
