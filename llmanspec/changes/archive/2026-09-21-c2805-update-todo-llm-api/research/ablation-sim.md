# 高频场景消融（JSON 字符，约 ÷4 为 token）

> 2026-09-21。脚本一次性跑出；内容约 55 字符/条。不是线上遥测。

## 场景

| 编号 | 序列 | 代表 |
|---|---|---|
| S1 | 建表 + 每条先 in_progress 再 completed（2n 次 tick） | 最常见逐步推进 |
| S2 | 建表 + 每次一批「完成当前 + 开始下一项」（n 次） | 模型一次改两项 |
| S3 | 完成一半后插入 2 条再继续 | 偶发追加 |
| S4 | 有 update 仍每步 rewrite（n=12，S1） | 训练先验失败态 |

## n=12（中等清单，高频主看这张）

| 场景 | A1 仅 rewrite 全表回包 | A2 update 但回全表 | **A3 update+ack** | A5 +add/remove ack |
|---|---|---|---|---|
| S1 逐步 tick | 57322 (100%) | 31378 (55%) | **5834 (10%)** | 5834 (10%) |
| S2 批量 tick | 29818 | 17347 (58%) | **5122 (17%)** | 5122 (17%) |
| S3 中途 +2 | 18614 | 13648 (73%) | 4493 (24%) | **2876 (15%)** |
| S4 仍整表 rewrite | 57322 | 57898 (101%) | **33974 (59%)** | 33974 (59%) |

n=6 / n=20 同构：S1 上 A3 分别为 A1 的 20% / 6%；A5 在纯 tick 上与 A3 **同数字**。

## 单包体积 n=12

| 包 | JSON 字符 |
|---|---|
| 全表 / rewrite args | 1133 |
| update 一条 status | 52 |
| rewrite ack | 201 |
| update ack（含 content） | 132 |
| 旧 `{id,status}` | 40 |

## 读数

1. **高频（S1/S2）A5 = A3。** add/remove 工具在热路径上零收益。
2. **A2 只省一半。** 省在 args（52 vs 1133），result 仍每步甩全表。今日 xylitol 接近 A2。
3. **A3 的第二刀是 ack。** S1 n=12 从 55% 再打到 10%。
4. **A5 只在 S3 追加上赢 A3**（24%→15%）。绝对值差 ~1.6k 字符 / 约 400 token，且追加不是每步发生。
5. **S4 失败态**：模型不听 guidelines、每步 rewrite 时，A3 仍因 ack 剩 59%；A5 帮不上。真要治 S4 得靠 prompt / 产品层拦 rewrite，不是加工具名。

结论：高频下最小有效集是 **A3**。A1 不修热路径；A2 漏掉 result；A5 为偶发追加扩闭集，ROI 低。
