# Design — 拆分边界与 r57 收窄口径

## 决策表

| # | 决策 | 取舍 |
|---|---|---|
| D1 | r57 MUST 收窄到「外部时序依赖」场景 | 全量包裹 churning 大且收益低（纯内存异步自有完成语义）；但零包裹又让防挂起合约空转——收窄到真正会挂的类别（网络/子进程/挂钟），配合「MUST NOT 文本自证」堵住名实不符。 |
| D2 | steps_c2827 拆分为「探针集中 + 行为按域」 | 文本探针是现实存在的一层（裸规则回填产物），与其伪装成行为步骤，不如集中到一个自我标注「结构探针」的模块，评审时可整体跳过。 |
| D3 | 步骤注册文本零变化 | rstest-bdd 注册表按文本匹配；场景↔步骤映射是 spec 对拍基线，拆分 MUST 是纯搬移。以 `check_bdd_steps` + BDD 全量对拍锁。 |
| D4 | W6 5ms 断言改「相对序 + 完成性」判据 | 壁钟绝对值随 CI 负载漂移；idle drain 的产品语义是「不阻塞、返回空」，以不超时 + 返回形状断言即可。 |
| D5 | W7 会话 id 解耦按「同场景族共用常量」 | 最小改动：c2842 系列步骤与 given 用同一命名常量（s-v3 / s-c2841 显式归属），消除跨规则隐式借用。 |

## 失败模式

- 拆分遗漏 `use` / thread_local 归属 → 编译期暴露（低风险）。
- W5 删 sleep 后读循环 3s 兜底不足 → 极端慢 CI 下失败一次即回退该单项（各自独立 commit 可回退）。
