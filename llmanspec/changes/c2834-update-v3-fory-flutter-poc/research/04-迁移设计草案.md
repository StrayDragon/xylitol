# 04 · 迁移设计草案(v3 方向性决策记录)

> 本篇是方向性设计与决策记录(含被否方案),供 `llman-sdd-propose` 时细化为 tasks/specs。标注 **[已定]** 的项基于 PoC 证据;标注 **[待定]** 的项 propose 时决策。

## 1. 总原则

- **协议 = 强 schema 区 + 动态区** 的混合体是终态,不是过渡态。分界线 = 今天 serde 类型签名里的「具体类型 vs `Value`/原文 String」(见 02 §3),fory 化不移动它,只把它升格为 fdl 显式声明。
- 单人工具,TUI 与 host 同步发版 → **不留线上长期双轨共存**;双轨是对拍验证手段,对拍通过后硬切。
- 不动项:幂等账本(幂等键 c2460)、writer 租约带外通道、InProcess 零序列化路径、journal 存储格式。

## 2. 信封设计(fdl 侧)

```
Frame = ClientRequest{ rpc_id: uint64, method_id: uint32, command: Command }
      | ServerResponse{ rpc_id: uint64, result: Response }        # 形态 propose 时定
      | ServerNotification{ seq: uint64, event: Event }
```

- **[已定]** `rpc_id` 承接现信封幂等键语义;`seq` 保留 journal 单调序号/resync 语义。
- **[已定]** 方法名不再过线:registry 38 行 `MethodEntry` 平移为编译期方法 ID 表(fdl `[id=N]` 分配);能力位(Auth/Idem/Resp/Exec)语义不变。
- **[已定]** 动态块(fdl `string` 原文):`ToolStart.args_json`、工具/环境输出、任何「形状由运行时决定」的载荷。`any` 不用(03 §3.1)。
- **[待定]** `ServerResponse.result` 的成功/错误形态:`RpcResult/RpcError` 的 fory 映射(错误码枚举 + detail)。
- **[待定]** 大载荷专用变体(get_messages/session_tree)是否单独 message(利于 Dart 端内存策略)。

## 2.5 字段名冲突盘点(已完成,基线 f4b8d68e)

fdl 保留字 + 标量类型名共 46 个(完整表:`fory/compiler/fory_compiler/frontend/fdl/lexer.py` KEYWORDS + xlang 标量)。对 v3 会进 fdl 的全部过线类型(wire 三件 + session 过线类型 + model 载荷,13 文件、去重 119 个字段名)扫描,**撞保留字的字段定义共 11 处、涉及 3 个词**:

| 保留字 | 处数 | 位置 | v3 建议名 |
|---|---|---|---|
| `message` | 8 | ErrorEvent / MessageStart / MessageEnd / MessageUpdate(event.rs:15,55,60,66)、Prompt / Steer / FollowUp(command.rs:13,104,107)、UserEntry.message(entries.rs:70) | `detail`(Error)/ `text`(Prompt)/ `msg`(Message*)/ Steer·FollowUp `text` / UserEntry `msg` |
| `list` | 1 | TodoUpdated.list(event.rs:110) | `todo_list`(PoC 已用) |
| `timestamp` | 2 | EntryBase.timestamp、SessionTreeNode timestamp(entries.rs:38,60) | `ts` |

**为什么这不是「很多 patch」**:

1. 改名只写在 fdl 文件一处;Rust 侧受影响的只有 v3 本来就要重写的代码(`to_wire_event` 映射层、host 下行构造、remote 消费)——生成物替换 serde enum 时字段名差异顺带发生,不构成额外 patch。
2. 领域层与持久化**零改名**:`XyEvent`(lifecycle)、`AgentMessage`、`SessionEntry` 磁盘格式(SESSION_VERSION=7)全部不动——fdl 只管 wire 投影。
3. Dart 端零手写(生成物自动跟随 fdl 名)。
4. 对拍器不付名字税:**对拍点设在领域对象层**(JSON 路径解码→`XyEvent` vs fory 路径解码→`XyEvent`),两条解码路径各自完成名字映射,比较的是同一领域对象,无需字段名映射表。

零改名备选(**不推荐**):fork foryc 的 parser 在字段名位置接受关键字 token(几行,与 `--rust-serde` 同一 fork)——可保 `message`/`list`/`timestamp` 原名,但 fdl 文件偏离官方语法(换回上游 compiler 不可编译),长期维护劣于 11 处改名。

## 3. server framework 决策

**[已定] fory 化不要求换框架;真正退役的是 jsonrpsee**(其存在意义即 JSON-RPC 分发)。三条路线已评估:

| 路线 | 结论 |
|---|---|
| 保留 salvo + 自研 fory 薄信封 | **推荐**:接缝本就收敛在 codec 层;换框架是独立决策不与 fory 绑死 |
| 换 axum | 合法但非必需(tower 生态 / tonic 亲缘是独立动机) |
| 换 tonic(gRPC,fory 官方有生成器) | **否**:flutter web 需 grpc-web 代理(个人 daemon 持续负担);自定义下行语义(seq/journal 重放/resync/合并窗口)塞进 gRPC 框框反而失真 |

调试面补偿(二进制的真实日常损失):xlang compatible 模式自描述(流内 TypeDef)→ 提供 `dump` 子命令把捕获帧解为可读 JSON;`/openapi.json` 保留为方法表文档(本就非客户端生成真源)。

## 4. 能力协商与版本

- **[已定]** `host.describe` 返回 wire formats 能力位;客户端不识别 → 致命(协议版本硬闸 ath44 的「不匹配即死、不重试风暴」语义原样迁移到格式协商)。
- **[已定]** 锁 fory release(1.7.5;crates.io 与 pub.dev 同号);两端同 commit。**锁版本的隐含语义**:daemon 与各端捆绑同一 fory 运行时;字段演进(compatible 模式)在格式稳定期内仍可各端独立。
- **[待定]** conformance 机制细节:字节级快照测试(抓真实流量锁 bytes)防上游 codec 漂移。

## 5. 双轨对拍方案(切换路径)

```
阶段 0(本草案已完成):PoC 证明链路通
阶段 1:全量协议 fdl 草稿(38 Command + 18 Event + 信封;字段名保留字盘点对照表)
        + fork foryc --rust-serde + xylitol 线协议 benchmark(JSON baseline)
阶段 2:双轨对拍——同一类型经 serde JSON 与 fory 两条路径,语义等价断言
        (BDD 步骤是现成语料;生成物带 serde 后对拍器零转换层)
阶段 3:propose 正式化:改 server-core.feature 信封合约(r1778/r1796/r1803/r1804)
        → jsonrpsee 退役 + WS 双帧分派(过渡期文本帧保留)→ 硬切 → 文本帧退役
```

- **[已定]** 切换触发点 = Flutter 端立项或远程场景落地;server-TUI 本机场景不构成动机。
- **[待定]** 阶段 3 的 WS 过渡帧分派细则(同一连接协商 vs 双端口)。
