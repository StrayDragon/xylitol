# 产品位：稳定线协议（Command/Event 闭集真源）

> **状态：purpose-draft** —— 只钉产品行为与契约，**不含技术实现、不列选项**（Event/Command 具体字段、命名、codec、实现切片由后续 change 填充）。
> 依据：`c2280` research `03`（消息路径）、`01`（信封/热路径），`c2300`（能力归属、启动与连接方式 A/B 已决、多窗写入规则）。

## Why

产品要"一个稳定协议的 CS 模式"：TUI 永远是薄客户端，与 host 之间的命令 / 事件契约必须是**唯一真源**。当前 wire 协议没有覆盖全部产品语义（存在不经线协议的旁路能力），且"进程内 vs 远程"有双语义风险。本 change 把线协议定型为**产品语义闭集**：面本地不进协议、禁双语义、旁路能力收敛，为多会话（c2302）、统一进线（c2303）、符合性闸（c2304）提供契约地基。

## What Changes

### 协议地位与稳定规则

- 线协议（Command / Event）是 **产品唯一真源**：TUI 与 host 之间的一切产品语义都表达为命令与事件。
- **契约与载体无关**：无论同一进程直连还是网络传输（c2300 已决默认 A），走同一套命令 / 事件契约；换载体不换语义。
- **禁双语义（0.0.1 前）**：不为同一个产品语义保留第二套表达；现有不经线协议的能力要么并入协议、要么下线。REST 不作为产品语义承载（仅调试 / 健康旁路或删除，c2280 结论）。
- **面本地不进协议**：剪贴板（含 OSC 52）、TTY、`$EDITOR`、键位、绘制只在客户端侧（c2300 归属），无协议表示。

### 语义词面（闭集覆盖的产品能力）

- 客户端 → host 的命令族：运行、中止、模型选择与 thinking、会话生命周期（新建 / 切换 / 命名 / 删除 / 导出 / 导入）、steer / follow-up / 队列、reload、信任持久化、工作区 bash（含 `!` / `!!`）、审批与问卷应答。
- host → 客户端的事件族：增量（文本 / thinking）、工具流（开始 / 更新 / 结束）、回合生命周期、反向 RPC 请求（审批 / 提问）、工作区 bash 增量与结果、会话状态。
- **会话标识**：每条命令与事件都归属到具体 session（多会话语义的基础）。
- **journal 订阅与回放**：客户端可订阅事件流、带续传位置（如序号）断开重连后回放、容量达到上限时要求客户端重新同步。
- **反向 RPC**：host 可以向客户端发起请求（审批工具 / 提问），客户端应答；第一个应答生效。

### 会话写入规则（接 c2300）

- 一条 session 同一时刻**只有一个写者**；host 据此决定是否接受一次写入。
- 已有其它客户端写入的 session 上，新 attach 只得到**只读静态恢复**视图；对其发起写（如 prompt）→ host 拒绝并给出「有其他 TUI 已连接，当前仅只读」的错误语义。
- host 在协议层面能表达"每 session 的客户端连接状况"（谁在写、谁只读）。

## 非目标（本 change）

- 不设计协议具体变体 / 字段 / 命名 / 实现切片（后续 change 填充）。
- 不做编码层二进制化（c2300 已判 tagged JSON 足够）。
- 不实现 server 多运行时（c2302）、不实现 attach 进线（c2303）、不实现符合性闸（c2304）——只提供它们依据的契约。
- **不引入 ACP / JSON-RPC 等第二协议面作为核心语义**：native Command/Event 是唯一真源；若未来要支持外部 ACP 客户端，以**外层适配器**消费本契约（单独决策，见 c2280 research `acp-interop.md`），不进核心协议闭集。
