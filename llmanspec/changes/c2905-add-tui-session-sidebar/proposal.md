# 会话侧栏（zellij 式驻列）：内容区让宽的常驻第二列

## Why

c2875 交付的瞬态抽屉（overlay）用户实机试用后确认：还需要**常驻驻列**形态——类似 zellij panel / opencode 边栏：右缘整列、宽度小、**内容区让宽重排**（换行按收缩后宽度，非覆盖截断），与瞬态抽屉并存、键位互相独立。

## What Changes

- 新增第二显隐形态「驻列（侧栏）」：`app.session.sidebar`（alt+i 之外的独立键 alt+u）二态切换；开启时根渲染进入 `内容宽 = 全宽 − 驻列宽` 的重排（wrap 缓存按内容宽键控，天然失效重建），右缘整高绘制 muted 分隔与信息列（与抽屉同数据：会话身份 / 模型 / thinking / 目录）。
- 通知栈与瞬态抽屉等 viewport overlay 右对齐改按**内容宽**收口，不得压住驻列。
- 驻列与抽屉状态互不影响；驻列开启路径同样经 host drain 供给会话身份。
- 上限纪律沿用：禁止宽度动画、无阴影卡片；AO 选区映射按内容宽口径（已知偏差记录于 design）。

## 非目标

- 不做左右可切换 / 多驻列 / 驻列内交互 / 拖拽调宽。
- 不动 host 层宽度档判定口径（极窄档下驻列挤压为已知取舍，见 design）。

## Capabilities

- `app-tui-fixed-zone`（r2904 会话侧栏；与 r2903 抽屉并列）

## Impact

- 根渲染宽度流单点改道（shadow），upper 缓存按内容宽失效重建一次。
- BDD：驻列开（右缘分隔 + 标题 + 内容让宽）/关（恢复全宽）；与抽屉互不扰动。
