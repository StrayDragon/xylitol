# 产品位：符合性闸（同一 Contract 双实现同跑）

> **状态：purpose-draft** —— 只钉产品级测试语义，**不含技术实现、不列测试框架选项**。
> 依据：`c2300`（能力归属、启动与连接方式）、`c2301`（稳定线协议闭集 ＝ 场景表的真源）、`c2302`（host 多会话 + 契约传输面）。

## Why

"稳定协议的 CS 模式"要有牙齿：**同一张 Command/Event 契约，在两种实现上跑出同一份可观察行为**——进程内实现（embed host 内驱动）与跨协议实现（测试 host + 契约客户端，走真实 transport）。Remote/契约客户端对已承诺语义返回未实现、或双实现行为漂移 → **闸红**。这是 c2280「双模代码 SSOT」硬规则 4 的落地，也是 c2303 attach 可用的质量地基。

## What Changes

### 一张场景表为真源

- 一份 **「简名 Command → 期望可观察 Event 序列」场景表**，真源来自 c2301 语义词面（运行 / 中止 / 模型与 thinking / 会话生命周期 / steer / follow-up / 队列 / reload / 信任 / 工作区 bash / 审批 / 问答 / 导出导入 / journal 订阅与回放）。
- 每条场景含错误语义（如拒绝、会话缺失、写者冲突），保证双跑对"失败路径"也一致。
- **补进规则**：未来新增协议语义 MUST 带场景（防"第二语义"回归）。

### 双实现同跑

- 同一场景表对 **(a) 进程内实现** 与 **(b) 测试 host + 契约客户端（跨协议）** 各跑一遍；同表同断言，结果一致才算绿。
- 契约客户端未经真 transport（c2302 传输面），不"mock 掉"协议——跑的是真实序列化 / 传输 / 反序列化。
- 任一实现对已承诺命令返回未实现 → 红。

### 面本地排除

- 剪贴板 / TTY / `$EDITOR`（c2300/c2301 面本地）**不进这张表**；其行为由 TUI 侧协作器单独覆盖（不因进线分叉）。

### 多窗 / 只读语义入表

- 对已被写入的 session 发起并发写 → 拒绝 / 只读提示的语义，也要双跑一致（c2300/c2301 会话写入规则）。

## 非目标（本 change）

- 不做协议 / host / attach 本身（c2301–c2303）。
- 不复制端到端全链路 BDD（本闸是契约层 / 组件边界，不是 E2E）。
- 不覆盖面本地（另归 TUI 侧）。
