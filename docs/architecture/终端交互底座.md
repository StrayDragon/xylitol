# 终端交互底座

> 用户/产品视角：终端里「稳、顺、可预期」。不写组件 API 与 crate 地图。
> 现状对齐：2026-07-18。

## 用户怎么碰到

用户不会说「引擎有质量债」。他们会说：输入/粘贴/快捷键怪、流式闪烁错位、某些终端里滚动补全不符合预期。

产品承诺的是：**主流终端上差分渲染与输入可预期**，且关键路径有自动验证护栏，让产品壳敢做视觉与信息优化。

## 产品规则（MUST / 禁止）

| MUST | 禁止 |
|---|---|
| 差分渲染 + 同步输出，流式时编辑区仍可用 | 为对齐上游而回退已作的刻意差异 |
| 键位（含 Kitty / 传统序列）与粘贴行为可预期 | 无台账的静默改键位/语义 |
| 易碎路径有合成层 + 真终端层验证 | 只靠手工点一点 |
| 准通用逻辑优先落通用引擎，再接线产品壳 | 把准通用逻辑堆进产品面 |

## 主线 vs 后置

| | 内容 |
|---|---|
| **已落地** | 差分渲染 / 终端协议 / 粘贴与补全高频路径 / 四层验证闸（合成 + 真终端） |
| **后置** | 持续卫生还债（热缓冲等）；与视觉主线解耦的定期质量债 |
