# 进程内观测

> 用户/产品视角：排障时对照「线路所见」与「产品理解」，并可选择把同一时间线导出到标准 OTLP / Langfuse。
> 现状对齐：2026-07-22。

## 用户怎么碰到

开发者或深度用户想回答：这一轮对上游发了什么、收回了什么？是线路上的内容错了，还是本地映射错了？过程树与工具状态如何？

今日可用：

1. **进程内对照底座**（本地时间线 / `provider-trace.jsonl` + 窄读脚本）
2. **可选 OTLP 出口**（配置显式开启；默认不收集）→ Langfuse 或其他 OTLP 后端
3. **同 turn 过程树**（开启观测时）：一次用户触发处理导出为 `agent.turn` 根，下挂 `agent.iteration` / `llm.request` / `tool.execute`；Session 聚合多轮，而非平铺散落根 traces

**不**自研 Inspect 检视台作主路径。

## 产品规则（MUST / 禁止）

| MUST | 禁止 |
|---|---|
| 显式调试档才持续记录敏感载荷 | 默认把完整请求体永久明文甩到不可控处 |
| 能对照「线路所见」与「产品理解」 | 只给映射后结果、无法证伪通道错分 |
| 用窄读工具/配方读本地 trace，不整文件灌进上下文 | 把外挂 MITM 写成产品主路径 |
| 远程 OTLP 默认关闭；坏配置降级不收集 | 因观测失败阻断对话主路径 |
| 时间线栈仅 fastrace + `log` | `tracing` 双栈 |

## 主线 vs 后置

| | 内容 |
|---|---|
| **已落地（M0–M4）** | 进程内时间线与本地对照；可选 OTLP；Langfuse session / generation / usage；同 turn 父子树与产品导出名 |
| **候补出口** | 见 [../roadmaps/OTEL与Langfuse观测.md](../roadmaps/OTEL与Langfuse观测.md)（子进程出站等） |
| **不做** | 自研 Web Inspect 台、TUI「只起检视页」作为主观测面 |
