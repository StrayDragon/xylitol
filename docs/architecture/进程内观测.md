# 进程内观测

> 用户/产品视角：排障时对照「线路所见」与「产品理解」。不写 Web 检视台 UI。
> 现状对齐：2026-07-18。

## 用户怎么碰到

开发者或深度用户想回答：这一轮对上游发了什么、收回了什么？是线路上的内容错了，还是本地映射错了？

今日可用的是**进程内对照底座**（本地时间线 / 对照记录 + 窄读脚本），**尚非**完整 Inspect 检视台。

## 产品规则（MUST / 禁止）

| MUST | 禁止 |
|---|---|
| 显式调试档才持续记录敏感载荷 | 默认把完整请求体永久明文甩到不可控处 |
| 能对照「线路所见」与「产品理解」 | 只给映射后结果、无法证伪通道错分 |
| 用窄读工具/配方读 trace，不整文件灌进上下文 | 把外挂 MITM 写成产品主路径 |

## 主线 vs 后置

| | 内容 |
|---|---|
| **已落地（M0）** | 进程内时间线与本地对照；排障配方 / 窄读入口 |
| **后置** | Web Inspect 模块、TUI 只起检视页、子进程出站覆盖、agent 友好查询 API |
