# 库与多客户端

> 用户/产品视角：同一内核如何被多种 client 与嵌入方共用。不写 API 签名与模块路径。
> 现状对齐：2026-07-21。

## 用户怎么碰到

- **TUI**：本地交互终端面（**CLI 默认入口**；走统一 XyDriver + 统一事件流）。
- **Print**：本地一次性对话，开箱主路径之一。
- **Server**：远程托管同一内核，经线协议对外；需启用对应能力。
- **远程薄端**：理想上连 Server 的独立客户端——**线协议已通，客户端产品面尚未接线**。
- **嵌入库**：外部程序把 xylitol 当库，自建界面。

用户改道（插话 / 续跑 / 中止）只经统一的「驱动」入口，不直达对话循环内部。

## 一条主线（产品）

```text
装配 → 驱动（进程内或远程）→ 对话循环 → 统一事件流 → 该面渲染
```

**心智（命名不改代码）**：`XyDriver` 是多 client（Print / TUI / Server / 嵌入 / 未来 Web）共用的**统一交互内核**——整机遥控器：跑一轮、改道、会话与模型命令都经此入口，不直达对话循环内部。实现类型名继续叫 Driver；产品面角色（如 TUI / Server）不必强行 `Xy*App` 品牌化。

```mermaid
flowchart LR
  Clients["Print / TUI / Server / 嵌入"] --> XyDriver["统一驱动 / 交互内核"]
  XyDriver --> Loop["对话循环"]
  Loop --> Events["统一事件流"]
  Events --> Render["各面各自渲染"]
```

## Client 矩阵

| Client | 角色 | 今日状态 |
|---|---|---|
| **TUI** | 本地交互（默认） | ✅ 已开闸并消费 XyDriver 事件流 |
| **Print** | 本地一次性对话 | ✅ 已走主线 |
| **Server** | 远程托管同一内核 | ✅ 已挂到统一驱动（配置/feature 启用） |
| **远程薄端** | 连 Server 的独立客户端 | 🔴 预留：线协议/队列可上线；无已交付远程客户端应用 |
| **嵌入库** | 外部自建面 | ✅ 公开装配缝 + 精选契约 |
| **GUI / Web（未来）** | 桌面或浏览器控制台 | 🔴 未开 |

## 两层对外契约（产品规则）

| 层 | 给谁 | 写什么 |
|---|---|---|
| **库契约（`Xy*`）** | 替换端口、跨面事件、**共享应用协议（`XyDriver`）**、配置元数据 | 精选稳定符号（见 `src/AGENTS.md` / crate 根 `pub use`） |
| **装配辅助** | 多 client / 嵌入方 | bootstrap、`BuildAgentOptions`、dispatch、（可选）线协议 |

需要新能力时扩 `XyDriver` / 事件 / 端口，不要伸手进内部实现。

**公共面体验（理想）**：TUI 与未来 Web 等已开闸面，对**共有**能力保持同一套用户学习模型与动作语义；快捷键尽量同构。面专属能力可分叉。候补约束板仍见 roadmaps「Web 与 TUI 同源」（未全部兑现前勿写成现行 MUST 清单）。

## 嵌入方产品规则

1. **优先**公开装配缝 + 精选库契约。
2. **不要**把内部实现类型当稳定 API。
3. 未配置的能力（如 MCP）必须 **zero-cost**。
4. 已知泄漏与非承诺项 → 一行见 `src/embed.rs` 文档注释；不在此展开。

## 理想 vs 现状

| | 状态 |
|---|---|
| Print / Server / 嵌入走统一驱动 | ✅ |
| TUI 消费同一事件流（会话树、steer、slash、bang…） | ✅ |
| CLI 默认进 TUI | ✅ |
| 线协议部分生命周期仍可降级 | 🟢 远程展示打磨中 |
| 独立远程薄端应用 | 🔴 未接线 |
| TUI ↔ Web 公共能力学习成本一套 | 🟢 理想；约束板在 roadmaps，Web 未开闸 |
| TUI 仅为薄客户端、操作器恒在 host 角色 | 🟢 产品位已立（默认仍同进程 embed）；多窗 attach / 独立监听器未接线 |
