# 多厂商模型

> 用户/产品视角：换模型不应换一套界面语言。不写 HTTP / 适配器细节。
> 现状对齐：2026-07-24。

## 用户怎么碰到

用户在配置、命令行或 TUI `/model` 里选一个模型（或换一家兼容端点）。对话里仍是：流式文字、思考、工具调用、结束——**同一套体验**。agent 还在跑时换模 / thinking：**当前流不换**，下一 turn 起用；见 [运行时即时设置.md](./运行时即时设置.md)。

OpenAI 兼容端点：**默认走 Responses**；只有端点不支持时才在配置里显式写 `api: openai-completions`（遗留逃生）。

```mermaid
flowchart LR
  User["用户 / 对话核心"] --> Same["同一套：流式文字 · 思考 · 工具调用 · 结束"]
  Same --> Adapters["各厂商适配（门后）"]
  Adapters --> A["OpenAI 兼容 · 默认 Responses · Completions 遗留"]
  Adapters --> B["Anthropic · Messages"]
  Adapters --> C["以后更多…"]
```

## 产品规则（MUST / 禁止）

1. **对外一种说话方式**：流式增量、工具请求、结束原因，对界面都一样。
2. **厂商差异关在门后**：某家 API 大改，优先在适配层消化；不要让界面学会「某厂商专用事件」。
3. **Pre-1.0 交付只两家**：OpenAI 兼容（**默认 Responses**；Completions 显式遗留）与 Anthropic（Messages）。用户自定义端点仅当声明为上述兼容 API 时接受。
4. **排障能看见方言**：观测时间线能对照本次请求用的 `api`（如 `openai-responses`）。
5. **禁止**：OAuth、专属 attribution header、其它厂商专属逻辑作为 1.0 前交付；禁止「已经是统一模型再包一层」的双路径产品故事。

## 主线 vs 后置

| | 内容 |
|---|---|
| **主线** | OpenAI 兼容默认 Responses + Anthropic；Completions 显式遗留；统一事件与工具调用体验；thinking 经 `/model`（默认支持集最高档） |
| **后置** | 更多厂商适配器与命名预设；抽象上留位，不为未交付厂商堆产品概念 |
