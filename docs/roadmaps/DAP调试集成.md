# DAP 调试集成

> 深度集成姊妹能力 **dapz**（`../dapz`）：让 agent 在调试适配器协议上省 token、可会话启停；与 LSP 一样遵循零成本默认。
> 现状对齐：2026-07-17。

## 用户怎么碰到

- 修 bug 时希望 agent 能断点、看栈、读变量，而不是只靠 `print`；
- DAP 原始载荷极大，需要压缩后再进模型语境（dapz 的存在理由）；
- 不是每次编码都要调试器——关则彻底无感。

## 与 lspz 的平行心智

| | LSP（lspz） | DAP（dapz） |
|---|---|---|
| 角色 | 语言智能（诊断/符号…） | 调试智能（栈/变量/断点…） |
| 默认 | 零成本 | 零成本 |
| 启停 | 会话内 / 即时设置 | 同左 |
| 中间层价值 | 压缩 LSP 响应 | 压缩 DAP 响应 |

```text
Agent ←→ dapz ←→ DAP 适配器（debugpy、lldb-vscode、…）
```

## 产品规则

| MUST | 禁止 |
|---|---|
| 未启用时不装配调试会话与 dapz | 启动 xylitol 即挂调试器 |
| 会话内或即时设置可启用/停用 | 只能改全局配置重启 |
| 进入模型的调试观察结果应是压缩后的可理解摘要 | 默认倾倒完整 DAP JSON |
| 调试生命周期可中止、可看见 | 后台断点会话用户不知情 |
| 高成本调试目标有档位或确认 | 对巨型进程默认全量变量展开 |

## BDD 意图示例

**场景：默认无感**
Given 用户未启用 DAP
When 普通编码对话
Then 无调试适配器与 dapz 常驻成本

**场景：启用后可调试**
Given 用户在本会话启用 DAP 集成
When 请求在断点处观察栈与变量
Then agent 能获得经 dapz 压缩的可理解调试信息（在环境支持的前提下）

**场景：即时关闭**
Given 调试集成已启用
When 用户经即时设置关闭 DAP
Then 下一波次不再装配；现有调试会话按明示规则结束或保留

## 分阶段

| 阶段 | 用户可感知结果 |
|---|---|
| M1 会话开关 | 启用/停用；默认关 |
| M2 只读观察 | 栈/变量/输出经 dapz 进入语境 |
| M3 可控动作 | 断点与继续/单步等（权限可感知） |
| M4 与即时设置/同源 | 开闭进开关盘；TUI/Web 状态一致 |

## 实现接缝（认领时 · 非现行 MUST）

| 接 | 不接 |
|---|---|
| 即时设置开闭 → 下一波次装配；经**统一工具口** + dapz 压缩摘要 | 插件式调试器市场 |
| 调试生命周期可中止、可看见（对齐插话/中止语义） | 绕过 Driver 的第二套调试总线 |
| 未启用零成本 | 启动即挂适配器 / 倾倒原始 DAP JSON |

## 支线与方向

| 支线 | 意向 |
|---|---|
| **与 LSP 共用开关盘 UX** | 「语言工具」分组：诊断 vs 调试并排，心智不分裂 |
| **条件断点 / 日志点** | M3 后的深度动作；默认仍要可感知权限 |
| **失败复现剧本** | 一键「按上次断点配置再跑」进 Eval 回归项 |
| **多适配器档案** | debugpy / lldb 等预设档位与内存策略 |
| **调试摘要进冷语境** | 与 [上下文缓存与极致压缩.md](./上下文缓存与极致压缩.md) 共享「中间层压缩再进模型」 |
