# Sub-Agent 编排

> 主会话可派生子 agent 分担子任务；产品上要可控、可看见、可中止，而不是静默分身。
> 现状对齐：2026-07-17。**提案级方向**，未进现行 architecture MUST。

## 用户怎么碰到

- 大任务希望「分头查 / 分头改」，主对话不被细节淹没；
- 需要知道有哪些子 agent 在跑、各自绑哪块上下文；
- 出错或跑偏时能收回、合并或丢弃结果。

## 产品目标

| 要 | 不要 |
|---|---|
| 显式的派生 / 回收 / 合并叙事 | 用户不知情的后台分身改仓库 |
| 子任务边界清晰（只读探查 vs 可写） | 子 agent 默认可越权于父会话信任 |
| 进度在 TUI/gpui **同源**可见 | 只在某一面有编排、另一面黑盒 |
| 与中止 / 插话语义可组合 | 子 agent 无视父级 abort |

## 领域语言

| 概念 | 含义 |
|---|---|
| **主会话** | 用户直接对话的会话 |
| **子 agent** | 由主会话派生的短命或可命名工作者 |
| **委托** | 交给子 agent 的目标与约束 |
| **回收** | 把子结果并回主会话语境，或丢弃 |

## BDD 意图示例

**场景：派生可见**
Given 用户或主 agent 发起一次子任务委托
When 子 agent 开始运行
Then 界面显示子 agent 存在与状态，且可导航查看其输出摘要

**场景：父级中止**
Given 子 agent 仍在运行
When 用户中止主会话本轮
Then 子 agent 按产品规则一并停止或进入可恢复的暂停，不继续静默改动

**场景：合并回主语境**
Given 子 agent 成功结束并带回结论
When 用户确认合并（或规则自动合并）
Then 主会话获得可理解的摘要，而非原始噪声倾倒

## 分阶段

| 阶段 | 用户可感知结果 |
|---|---|
| M1 提案固化 | 委托/权限/可见性产品规则进 llmanspec |
| M2 只读子探查 | 子 agent 可检索/阅读，默认不可写 |
| M3 可控可写 | 显式授权下可改；回收与冲突叙事清晰 |
| M4 多面编排 | gpui 总览多子任务；TUI 深会话内操作（同源语义） |

## 实现接缝（认领时 · 非现行 MUST）

| 接 | 不接 |
|---|---|
| 经 Driver / 统一生命周期事件表达派生、进度、回收 | 静默后台分身；第二套编排总线 |
| 权限不超过父会话 Trust；可写须显式授权 | 子 agent 默认越权 |
| 父级中止可组合传到子任务 | 无视 abort 的独立生命周期 |

## 支线与方向

| 支线 | 意向 |
|---|---|
| **只读探查舰队** | 多个短命只读子 agent 并行检索，主会话只收摘要 |
| **命名常驻工作者** | 可复用的「文档官 / 测试官」角色（权限仍不越父） |
| **回收压缩策略** | 合并默认走摘要；原始轨迹仅调试档可见（挂缓存 roadmap） |
| **Sub-agent Eval** | 委托成功率、越权拦截率进回归集 |
| **Loop 派生子任务** | 与 Loop 策略交叉：定时任务可否派生（默认否） |
| **成本预算帽** | 子 agent 合计 token / 轮次上限，超限可感知停 |
