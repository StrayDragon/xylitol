# 出口流量检视

> 自研 **Inspect（检视台）**：出站流量可预览、可关联、对人类与 agent 友好。
> **不采用外挂 MITM** 作主路径。可先**独立检视页**，再融入全日用 Web 控制台；TUI 可附带只起页。
> 现状对齐：2026-07-20。
> 进程内对照底座已在 architecture；本文只留检视台产品面。

## 用户怎么碰到

排障时打开检视台 → 按会话/时间线浏览 → 需要时交给 agent 结构化解读。

## 范围

| 层级 | 内容 | 承诺 |
|---|---|---|
| **A · 第一方出站** | xylitol 自身 HTTP 等 | **必须**进检视事实源 |
| **B · 托管子进程出站** | bash / MCP 等子进程对外请求 | **要覆盖**；可增强波次 |
| **非目标** | 劫持无关进程 | 不做「全球 MITM」 |

## 应用面形态

| 形态 | 说明 | 阻塞关系 |
|---|---|---|
| **独立检视页** | 仅含 Inspect 模块；可供 TUI「只起」或浏览器直开 | **可先于**完整多工作区控制台 |
| **Web 全日用模块** | 控制台 Logging / Inspect | 挂 [Cloud-Agent与Web控制台.md](./Cloud-Agent与Web控制台.md) |
| **agent 友好** | 同一事实源可结构化消费 | 与独立页同源；不另起账本 |

## 产品规则

| MUST | 禁止 |
|---|---|
| 显式开启检视才持续记录敏感载荷 | 默认把完整请求体永久明文甩到不可控处 |
| 记录可按会话 / 一轮 / 用途过滤 | 只有无法关联的原始字节 |
| A 范围缺记视为产品缺陷 | 用「去装 mitmproxy」替代承诺 |
| B 范围策略透明 | 假装已全捕获却静默漏子进程 |
| 多入口指向同一事实源 | TUI 只起页与 Web 模块各抓各的 |

## 分阶段（可认领切片）

| 阶段 | 用户可感知结果 | 备注 |
|---|---|---|
| **M1 事实源 A + 显式开启** | 第一方出站可关联进检视记录；默认不落敏感全文 | 底座之上的产品面；**不**要求多工作区壳 |
| **M2 独立检视页 / TUI 只起** | 参数或入口打开**仅检视模块**的页面 | 与 Cloud-Agent「检视模块可独立」对齐 |
| **M3 agent 查询** | 同一事实源可结构化交给 agent | 可与 M2 并行设计 |
| **M4 范围 B** | 托管子进程出站策略透明、可增强 | 可单独波次 |
| **M5 全日用控制台模块** | 检视嵌入多工作区 Web | **后置**于独立页 |

## 依赖与并行

- **硬依赖**：进程内对照底座（已落地）。
- **软依赖**：[Web与TUI同源.md](./Web与TUI同源.md) 的检视事实源约定（M3）。
- **不硬阻塞于**完整 Cloud-Agent：独立页可先交付；全日用模块再并入。
- 可与 Tokenizer / 多模态 / TUI 视觉并行。

## BDD 意图示例

**场景：TUI 附带只起检视页**
Given 用户以附带检视参数启动 TUI
When 需要查看本进程出口流量
Then 打开**仅含检视模块**的页面，无需完整多工作区控制台

**场景：显式开启才记敏感载荷**
Given 用户未开启检视记录档
When 正常对话产生出站请求
Then 不把完整请求体默认永久明文落到不可控处
